## 1. 이 사양이 맞추는 것 / 맞추지 않는 것

**패밀리룩을 값이 아니라 구조에 둔다.**

| 맞춘다 | 맞추지 않는다 |
|---|---|
| 토큰 **이름**과 그 이름이 가리키는 **뜻** | 토큰 **값**(팔레트) — 라이트/다크 두 벌을 유지한다 |
| 알림 문법(등급 × 수명) | 알림을 놓는 자리(상태 바 ↔ 토스트) |
| 치수 램프(글자 크기·둥글기·테두리) | 기존 여백값 일괄 교체 |
| 글리프 어휘(같은 뜻엔 같은 글리프) | 글꼴 — 이미 같다(할 일 없음) |
| "색만으로 구분하지 않는다" 규칙 | 앱 고유 의미색(§8) |

### 왜 명도를 맞추지 않는가

- MSM 을 라이트로 끌면 **앱의 성격을 부순다.** 터미널 다중 세션 앱이고 `xterm` 테마까지
  다크로 묶여 있다(`renderer.js:1123~1126`).
- FolderDeck 을 다크로 끌면 23개 값을 전부 다시 정해야 하는데, `DynamicResource` 가 0이라
  그 작업이 지금 구조에서는 화면에 반영되지 않는다(§7).
- **이름이 맞아 있으면 FolderDeck 다크가 나오는 날 값까지 자연히 정합된다.** 그때 채울 열이
  §4 의 "다크" 열이고, 그 열의 상당 부분은 MSM 이 이미 실물로 쓰고 있는 값이다.

이것이 이 사양의 핵심 판단이다. 명도 통일은 **버린다**, 이름·문법 통일은 **따온다**.

### 우선순위 규칙

> **정합 작업의 순서는 "지금 무엇을 막고 있는가"로 정한다.**

색 리터럴 162건은 테마를 막는다 → 고친다.
여백 불일치는 아무것도 막지 않는다 → 램프만 정하고 기존 값은 놔둔다.
40군데를 건드려 시각 회귀를 무릅쓸 값이 없다.

## 3. 토큰 이름 규약

**WPF `Brush.PascalCase` ↔ CSS `--kebab-case`** — 기계적으로 대응한다.

```
Brush.TextSecondary   ↔   --text-secondary
Brush.RowHover        ↔   --row-hover
```

- 새 이름을 지을 때 **양쪽에서 동시에 정한다.** 한쪽만 짓고 나중에 맞추면 반드시 갈린다.
- MSM 은 `:root` 에 정의하고 `var(--x)` 로만 참조한다. 리터럴을 새로 쓰지 않는다.
- FolderDeck 은 `LightTheme.xaml:7` 의 규칙("컨트롤에 `#RRGGBB` 를 직접 쓰지 말 것")을
  유지한다. **이 규칙을 이 사양의 양쪽 공통 규칙으로 승격한다.**

### 4.3 정리 항목 (0-A §5 에서 나온 것)

- **`Brush.DropInvalidSurface` — 남긴다.** ~~삭제한다~~ **(2026-07-30 정정)**
  이 문서의 초판은 참조 0건을 근거로 삭제를 지시했고 **그 근거가 틀렸다.**
  `TileGridView.xaml.cs:205` 가 `FindResource("Brush.DropInvalidSurface")` 로 실제로 쓴다 —
  **배치 편집 모드의 타일 겹침 미리보기**이고 바로 다음 줄이 `"겹침 — 놓을 수 없다"` 다.
  지웠으면 그 표시가 런타임 예외로 죽었다.
  - **오판의 경위를 남긴다**: 참조 0(실은 0-A 의 계수 방식 탓)에 설계 §4.2 "받지 않는 자리는
    과녁을 켜지 않는다"를 붙여 "쓰이지 않는 것이 규칙의 결과"라는 해석을 만들었다.
    §4.2 는 **파일 드래그앤드롭** 규칙이고 겹침 미리보기는 **§3.2 배치 편집** 규칙이다.
    **다른 절의 규칙을 끌어와 관측을 설명하면 그럴듯하고 틀린 결론이 나온다.**
  - 코드에 왜 남겼는지 주석이 붙어 있다. 그 주석을 지우지 않는다.
- **`RotatingSurface` 와 `RowActive` 는 값이 같지만(`#EDE7F6`) 키 둘을 유지한다.** 뜻이 둘이다
  (타일 면 / 행 활성). 다크에서 갈릴 수 있고, "색은 뜻 하나씩"은 값이 아니라 뜻의 규칙이다.
- **`SelectionSurface` 와 `RowActive` 는 자리가 다르다.** 앞은 **파일 목록 항목**(타일 안), 뒤는
  **왼쪽 폴더 리스트 행**이다. 값도 다르다(`#FFCCEFFE` ↔ `#EDE7F6`) — `RotatingSurface` 처럼 값이
  같아 헷갈리는 경우가 아니라, 구별할 것이 **뜻과 자리**다. 공유 코어로 올리지 않는 근거는 MSM
  세션 목록이 한 번에 하나만 고른다는 것이다(2026-08-05 실측 · `focusedSessionId` 단일 스칼라).
- **MSM `StateIdle` 은 전용 색이 아니다** — `#8b949e` 로 `TextSecondary` 와 같다. 새 토큰을
  만들지 말고 `TextSecondary` 를 쓴다(유휴 = 강조하지 않음이라는 뜻과도 맞는다).

## 6. 글리프 어휘

양쪽 다 아이콘 폰트·이미지 리소스가 0이고 **유니코드 글리프 직접 입력**만 쓴다. 그것을 사실로
받아들이고 어휘를 못박는다 — 같은 뜻에는 같은 글리프.

| 뜻 | 글리프 | 현재 |
|---|---|---|
| 새로 만들기·추가 | `＋` | **양쪽 이미 같다**(FolderDeck 빈 칸 · MSM 새 탭) |
| 완료 | `✓` | MSM. FolderDeck 에 쓸 자리가 생기면 이것 |
| 닫기·지우기 | `✕` | FolderDeck |
| 폴더 / 파일 | `📁` / `📄` | FolderDeck 만(MSM 에 파일 목록 없음) |
| 이동·탐색 | `←` `→` `↑` `⌂` `⟳` `🔍` | FolderDeck 만 |
| 세션 실행중 / 유휴 | `🟢` / `⚪` | MSM 만 |

**규칙**: 상태를 글리프로 표시할 때 **글자를 병기한다**(`🟢 실행중`). 색·글리프만으로 뜻을
나르지 않는다 — 설계 §3.2 의 색맹 대비 규칙과 같은 결이다.

**미결**: 컬러 이모지(📁🟢)는 플랫폼·글꼴에 따라 모양이 갈린다. 유지할지 단색 글리프로 갈지
→ §10. 지금은 **유지**가 현상이고 양쪽이 이미 그렇다.

## 7. 테마 교체 방식 (FolderDeck)

`App.xaml:9` 주석은 "이 딕셔너리 하나만 갈아끼우면 앱 전체가 다크가 된다"고 적었으나
**`DynamicResource` 가 0건이므로 지금 구조로는 런타임에 반영되지 않는다**(0-A §B).

**239곳을 `DynamicResource` 로 바꾸지 않는다.** 대신 **테마 교체를 재시작 범위로 못박는다.**

- 시작 시 설정값을 읽어 해당 딕셔너리를 병합한다. `StaticResource` 239곳은 그대로 둔다.
- 이 앱에서 런타임 즉시 전환이 필요한 자리가 없다. 워크스페이스를 여는 것 자체가 창을 새로
  띄우는 동작이다(설계 §6.2 — 워크스페이스당 프로세스 하나).
- `DynamicResource` 로 가면 참조 239곳의 조회 비용과 실패 시 조용한 폴백을 새로 안게 되는데,
  얻는 것은 "재시작 없이 바뀐다" 하나다.
- **`App.xaml:9`·`LightTheme.xaml:4` 의 주석을 사실대로 고친다** — "딕셔너리를 시작 시 골라
  병합한다. 런타임 교체는 지원하지 않는다."

다크를 실제로 착수하면 `settings.json` 에 `theme` 필드가 늘어 **전역 설정 `schemaVersion` 이
1 → 2** 가 된다(설계 §7.2). 워크스페이스 스키마(현재 5)와는 무관하다.

## 8. 앱 고유로 남기는 것

**의미 축이 서로 다르다.** 억지로 짝지으면 둘 다 거짓이 된다.

| FolderDeck 고유 | MSM 에 대응물 |
|---|---|
| 타일 상시/순환 (호박/보라, 실선/점선) | **있다** — 4×4 Session Deck 의 고정/순환 타일(`session-deck-review.md` §2). 색·글리프 규약은 다르다 |
| 드롭 과녁 (파랑 + "여기에 놓기") | 없음 — 드래그앤드롭 0건(`dragover` 검색 0) |
| 배치 편집 모드 (오버레이·격자선) | **있다** — 격자·손잡이·겹침 빨간 미리보기·`배치 취소`/`배치 완료`(`session-deck-review.md` §4) |
| 파일 목록 상세 뷰(`GridView` 컬럼) | 없음 |

| MSM 고유 | FolderDeck 에 대응물 |
|---|---|
| 세션 상태 축 (실행중/완료/유휴/주의) | 없음 |
| 터미널 면(`xterm` 테마) | 없음 |
| 탭 스트립 2층 | 없음(탭은 대상함/매크로 2개뿐) |

**단, 문법은 공유한다.** 상태를 색으로 나를 때 ① 이름 있는 토큰을 쓰고 ② 글자를 병기하고
③ 한 색에 뜻 하나. 이 셋은 양쪽 다 적용된다.

Phase 5 에서 FolderDeck 에 **외부 드래그앤드롭**이 들어가도 **드롭 과녁 행은 바뀌지 않는다** —
MSM 에 드롭 대상이 생기는 것이 아니다. 반면 **타일 행과 배치 편집 행은 2026-08-24 에**
**바로잡았다** — MSM 에 4×4 Session Deck 이 생겼다(`session-deck-review.md` §2·§4). 그 둘은
더는 「고유」가 아니지만, **타일 UX 는 정합 범위에서 제외**하기로 했으므로 표에 남긴다.
파일 목록 상세 뷰 행은 그대로 유효하다.

## 9. 공유 수단과 파생 작업

### 공유 수단

**이 문서 하나가 원본이다.** `FolderDeck` 저장소의 `doc/` 에 둔다(설계 문서가 이미 여기 있다).
MSM 쪽은 `README` 나 `styles.css` 머리 주석에서 **경로로 가리킨다** — 복사하지 않는다.
두 벌이 되면 갈린다.

**생성기(토큰 정의 → XAML + CSS 자동 생성)는 만들지 않는다.** 앱 둘, 언어 둘, 팔레트 둘,
공유 코어 14개다. 생성기 유지비가 손으로 맞추는 비용을 넘는다. 대상이 셋을 넘고 팔레트를
공유하게 되면 그때 다시 본다.

### 작업 순서

| 1 | MSM | `:root` 에 §4.1 이름으로 토큰 정의 + `styles.css` 162 리터럴 치환 + JS 5건 | 그 자체로 값이 있다 — 다크 팔레트가 이름을 얻는다. 이후 다크 열의 근거가 된다 |

섞지 않는다** — 성격이 다르고, 이쪽은 시각 회귀를 눈으로 봐야 한다.

### 정합 대상 범위

0-A §I 가 UI 프로젝트 다섯 · 프레임워크 넷(WPF · Electron · WinForms · Tauri)을 찾았다.
**지금 대상은 둘로 유지한다.** 다만 이 사양을 **프레임워크 중립으로** 쓴다 — §4 는 토큰
이름과 뜻이고, §5·§6·§7 은 XAML/CSS 문법에 의존하지 않는다. `WindowsTrayTranslator`(WinForms)나

## 10. 미결

- MSM `font-size: 9px` 9건 — 램프에 9 를 넣을지, 10 으로 올릴지 (§5).
- 컬러 이모지 유지 vs 단색 글리프 (§6). 지금은 유지가 현상.
- `CardSurface` 의 FolderDeck 쪽 대응 — 0-A 에 없어 **확인 못 함**. 런처 카드가 전용 토큰을
  쓰는지 `Chrome` 을 쓰는지 코드에서 봐야 한다.
- `AccentSurface`·`DangerSurface`·`RowActive` 의 다크값 (§4.1) — 다크 착수 시 실측.
- §4.2 앱 고유 토큰의 반대 명도 짝 — 지금 정할 근거가 없다.
- 창 최소 크기의 실제 값 (§5) — 실측.
- **두 앱이 창 위치 저장을 각자 구현했다**(0-A §5-8: `WindowPlacement.cs` ↔
  `window-placement.js`). 시각이 아니라 동작이라 이 사양의 범위 밖이다. 공유·정합 여부는
  별도 판단 — 0-A 도 내용을 비교하지 않았다.

## 11. 이 사양이 낳는 설계 문서 수정 항목

`doc/FolderDeck_design.md` 에 반영할 것. **앞서 정리한 SOT 정정 항목과 합쳐 한 번에 던진다.**

1. **§1.2 아이콘 문장 정정** — "v1은 확장자 기반 단순 아이콘"이 코드와 어긋난다. 코드는
   폴더/파일 두 갈래뿐이고 확장자를 보는 코드가 없다(0-A §5-4, `FileItemViewModel.cs:34`).
   → **문서를 코드에 맞춘다**: "v1 은 폴더/파일 두 갈래 글리프. 확장자 기반 구분은 넣지 않는다."
   이유: 아이콘 폰트·이미지 리소스가 0이고 글리프 어휘가 패밀리룩의 일부가 됐다(§6).
   확장자별 글리프를 늘리면 그 어휘표가 앱 하나 쪽으로 비대해진다.
2. **§8 에 테마 교체 범위 한 줄** — 재시작 범위이고 `DynamicResource` 로 가지 않는다(§7).
   근거를 같이 적는다.
3. **§1.2 비목표에서 "Shell 아이콘은 후순위"의 근거 보강** — 양쪽 앱이 다 안 쓴다는 사실이
   생겼다(0-A §H). 후순위가 아니라 **패밀리룩 결정으로 안 쓴다**로 격이 올라간다.
4. **§7.2 전역 설정** — 다크 착수 시 `theme` 필드로 `schemaVersion` 2 가 된다는 예고(§7).
   지금 필드를 만들지는 않는다.
